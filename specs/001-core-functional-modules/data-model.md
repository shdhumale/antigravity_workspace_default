## Entity Definitions

### 1. `users`

**Purpose**: Stores all user accounts. Soft-delete via `deleted_at`.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `VARCHAR(36)` | PK, UUID | Generated by JPA `UUID` strategy |
| `email` | `VARCHAR(255)` | UNIQUE, NOT NULL | Indexed (`idx_users_email`) |
| `password_hash` | `VARCHAR(255)` | NOT NULL | BCrypt(12 rounds) |
| `first_name` | `VARCHAR(100)` | NOT NULL | |
| `last_name` | `VARCHAR(100)` | NOT NULL | |
| `role` | `ENUM('ADMIN','MANAGER','VIEWER')` | NOT NULL, DEFAULT 'VIEWER' | |
| `mfa_enabled` | `TINYINT(1)` | NOT NULL, DEFAULT 0 | |
| `mfa_secret` | `VARCHAR(255)` | NULL | AES-256 encrypted at rest |
| `is_active` | `TINYINT(1)` | NOT NULL, DEFAULT 1 | `false` = deactivated |
| `failed_login_count` | `INT` | NOT NULL, DEFAULT 0 | Reset on successful login |
| `locked_until` | `DATETIME` | NULL | NULL = not locked |
| `created_at` | `DATETIME` | NOT NULL | Set on insert |
| `updated_at` | `DATETIME` | NOT NULL | Auto-updated |
| `deleted_at` | `DATETIME` | NULL | Soft-delete timestamp |

**Validation rules**:
- `email` MUST match RFC 5322 format (`@Email`)
- `password_hash` is never returned in API responses
- `mfa_secret` is only readable internally; never in API responses

**JPA Entity**: implements `UserDetails`; `@Table(indexes = { @Index(name="idx_users_email", columnList="email", unique=true), @Index(name="idx_users_role", columnList="role") })`

**Liquibase changeset**: `001-create-users.xml`

### 2. `refresh_tokens`

**Purpose**: Tracks issued refresh tokens for rotation and stolen-token detection.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `VARCHAR(36)` | PK, UUID | |
| `user_id` | `VARCHAR(36)` | NOT NULL, FK → `users.id` | CASCADE DELETE |
| `token_hash` | `VARCHAR(255)` | NOT NULL, UNIQUE | bcrypt hash of raw token |
| `issued_at` | `DATETIME` | NOT NULL | |
| `expires_at` | `DATETIME` | NOT NULL | `issued_at + 7 days` |
| `revoked_at` | `DATETIME` | NULL | Set when rotated or on logout |
| `replaced_by_id` | `VARCHAR(36)` | NULL, FK → `refresh_tokens.id` | Chain for reuse detection |

**State transitions**: `active` (revoked_at NULL) → `revoked` (revoked_at set).

**Business rules**:
- Reuse of a revoked token triggers immediate revocation of the entire rotation chain from that
  token forward.
- Expired tokens (expires_at < NOW()) are rejected regardless of revoked_at.

**Liquibase changeset**: `002-create-refresh-tokens.xml`

### 4. `products`

**Purpose**: Core product catalogue entity.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `VARCHAR(36)` | PK, UUID | |
| `sku` | `VARCHAR(50)` | NOT NULL, UNIQUE | Auto-generated on create |
| `name` | `VARCHAR(255)` | NOT NULL | FULLTEXT indexed |
| `description` | `TEXT` | NULL | FULLTEXT indexed |
| `category_id` | `VARCHAR(36)` | NOT NULL, FK → `categories.id` | |
| `price` | `DECIMAL(10,2)` | NOT NULL, CHECK > 0 | |
| `inventory_qty` | `INT` | NOT NULL, DEFAULT 0, CHECK >= 0 | |
| `status` | `ENUM('DRAFT','PENDING','ACTIVE','REJECTED','ARCHIVED')` | NOT NULL, DEFAULT 'DRAFT' | |
| `rejection_reason` | `TEXT` | NULL | Populated on REJECTED status |
| `created_by` | `VARCHAR(36)` | NOT NULL, FK → `users.id` | |
| `approved_by` | `VARCHAR(36)` | NULL, FK → `users.id` | Set on ACTIVE status |
| `version` | `INT` | NOT NULL, DEFAULT 0 | JPA `@Version` — optimistic locking |
| `created_at` | `DATETIME` | NOT NULL | |
| `updated_at` | `DATETIME` | NOT NULL | |

**Status lifecycle**:
```
DRAFT → PENDING (Manager submits)
PENDING → ACTIVE   (Admin approves)
PENDING → REJECTED (Admin rejects with comment)
REJECTED → DRAFT   (Manager revises)
ACTIVE → ARCHIVED  (Admin archives)
```

**Indexes**:
- `FULLTEXT INDEX ft_products_search (name, description)` — used by `MATCH … AGAINST`
- `INDEX idx_products_status (status)`
- `INDEX idx_products_category (category_id)`
- `INDEX idx_products_price (price)`
- `INDEX idx_products_created_by (created_by)`

**JPA annotations**: `@Version private Integer version;` on the version field.

**Liquibase changeset**: `004-create-products.xml`

### 5. `product_images`

**Purpose**: Uploaded images associated with a product.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `VARCHAR(36)` | PK, UUID | |
| `product_id` | `VARCHAR(36)` | NOT NULL, FK → `products.id` | CASCADE DELETE |
| `storage_url` | `VARCHAR(1000)` | NOT NULL | Local path or S3 URL |

**Business rules**: Max 10 images per product (enforced in `ProductService`).

### 6. `audit_log`

**Purpose**: Immutable record of all write operations across all entities.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `BIGINT` | PK, AUTO_INCREMENT | High-volume; BIGINT avoids overflow |
| `entity_type` | `VARCHAR(50)` | NOT NULL | e.g., `USER`, `PRODUCT` |
| `entity_id` | `VARCHAR(36)` | NOT NULL | UUID of affected entity |
| `action` | `ENUM('CREATE','UPDATE','DELETE','STATUS_CHANGE')` | NOT NULL | |
| `performed_by` | `VARCHAR(36)` | NOT NULL, FK → `users.id` | Actor user ID |
| `performed_at` | `DATETIME(3)` | NOT NULL | Millisecond precision |
| `old_value` | `JSON` | NULL | Serialized state before change |
| `new_value` | `JSON` | NOT NULL | Serialized state after change |

**Immutability**: No UPDATE or DELETE on `audit_log` is permitted. Table has no `@Version`; rows
are insert-only. Application role (DB user) has INSERT + SELECT only on this table.

**Indexes**:
- `INDEX idx_audit_entity (entity_type, entity_id)`
- `INDEX idx_audit_actor (performed_by)`
- `INDEX idx_audit_time (performed_at)`

**Liquibase changeset**: `006-create-audit-log.xml`

### 8. `approval_requests`

**Purpose**: Tracks product approval workflow state.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `VARCHAR(36)` | PK, UUID | |
| `product_id` | `VARCHAR(36)` | NOT NULL, FK → `products.id` | |
| `requested_by` | `VARCHAR(36)` | NOT NULL, FK → `users.id` | Manager who submitted |
| `reviewed_by` | `VARCHAR(36)` | NULL, FK → `users.id` | Admin who reviewed |
| `status` | `ENUM('PENDING','APPROVED','REJECTED')` | NOT NULL, DEFAULT 'PENDING'` | |
| `comment` | `TEXT` | NULL | Required when REJECTED |
| `created_at` | `DATETIME` | NOT NULL | |
| `resolved_at` | `DATETIME` | NULL | Set when APPROVED or REJECTED |

**Business rules**: At most one PENDING `approval_requests` row per product at a time
(enforced by `ProductApprovalService`).

## Angular Model Interfaces

```typescript
// core/models/user.model.ts
export type UserRole = 'ADMIN' | 'MANAGER' | 'VIEWER';

export interface User {
  id: string;
  email: string;
  firstName: string;
  lastName: string;
  role: UserRole;
  isActive: boolean;
  mfaEnabled: boolean;
  createdAt: string; // ISO-8601
}

// core/models/product.model.ts
export type ProductStatus = 'DRAFT' | 'PENDING' | 'ACTIVE' | 'REJECTED' | 'ARCHIVED';

export interface Product {
  id: string;
  sku: string;
  name: string;
  description: string;
  categoryId: string;
  price: number;
  inventoryQty: number;
  status: ProductStatus;
  rejectionReason?: string;
  createdBy: string;
  approvedBy?: string;
  images: ProductImage[];
  version: number;
  createdAt: string;
  updatedAt: string;
}

export interface ProductImage {
  id: string;
  storageUrl: string;
  fileName: string;
  displayOrder: number;
}

// core/models/audit.model.ts
export type AuditAction = 'CREATE' | 'UPDATE' | 'DELETE' | 'STATUS_CHANGE';

export interface AuditLog {
  id: number;
  entityType: string;
  entityId: string;
  action: AuditAction;
  performedBy: string;
  performedAt: string;
  oldValue: Record<string, unknown> | null;
  newValue: Record<string, unknown>;
}

// core/models/notification.model.ts
export interface Notification {
  id: string;
  eventType: string;
  title: string;
  body: string;
  isRead: boolean;
  createdAt: string;
}
```
